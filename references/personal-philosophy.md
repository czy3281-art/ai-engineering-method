# Personal philosophy behind this skill

The user prefers a voice-first, theory-first way of working. Repetitive, low-information-density work—syntax recall, software navigation, code typing, document triage, and mechanical formatting—should be delegated to AI whenever practical.

The user wants to spend time on mathematics, physics, communication theory, DSP, digital circuits, FPGA architecture, PCB rules, abstraction, system design, experimental reasoning, and new ideas. The user does not want line-by-line code reading or tool-specific操作 to become a prerequisite for meaningful engineering work.

The intended division is:

- human: choose the problem, understand the theory, design the architecture, state constraints, define tests, judge evidence, and create new questions;
- AI: implement, search, organize, operate tools, generate variants, run checks, and iterate.

This is a personal strategy, not a universal claim that every profession must abandon detailed implementation knowledge. For the user's communication, FPGA, embedded, PCB, and research work, the strategy is to move attention upward from tool syntax to transferable concepts and verifiable outcomes.

The user accepts AI implementation only together with original evidence: simulation waveforms, timing and resource reports, DRC/ERC results, logs, measurements, and source references. AI may summarize and audit evidence, but must not replace it.
